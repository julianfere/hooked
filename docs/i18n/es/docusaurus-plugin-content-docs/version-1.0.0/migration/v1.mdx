# Migrar a 1.0

:::danger[Cambios incompatibles]
1.0 es una **versión major** con cambios incompatibles. Requiere React 19 y cambia la firma de `useAsync`. Leé esta página antes de actualizar desde 0.x.
:::

## Resumen

| Cambio | Tipo | Qué tenés que hacer |
|--------|------|---------------------|
| Se requiere React 19 y `react` pasa a ser peer dependency | **Incompatible** | Actualizar React a 19 |
| `useAsync` recibe el `AbortSignal` como primer argumento | **Incompatible** | Mover el parámetro `signal` al principio |
| `useDocumentTitle` deprecado | Deprecación | Renderizar `<title>` (opcional hasta 2.0) |
| Fixes en `useDebounce`, `useDelay`, `useQueryParams`, `useLocalStorage` | Fix | Revisá las notas de abajo si dependías del comportamiento anterior |
| Tipos públicos exportados | Novedad | — |

## Se requiere React 19 {/* #react-19-is-required */}

`react` pasó de `dependencies` a `peerDependencies` (`^19.0.0`). Antes de 1.0 la librería podía instalar su propia copia de React, lo que provocaba errores `Invalid hook call`. Ahora siempre usa el React de tu app.

```bash
pnpm add react@^19 react-dom@^19 @julianfere/hooked@^1
```

Si todavía no podés actualizar React, quedate en `@julianfere/hooked@0.3`.

## `useAsync`: signal primero {/* #useasync-signal-first */}

El `AbortSignal` ahora es el **primer** parámetro de tu función. Los argumentos de `trigger` vienen después.

```ts
// ❌ 0.x
const { trigger } = useAsync((id: string, signal: AbortSignal) =>
  fetch(`/api/usuarios/${id}`, { signal })
);

// ✅ 1.0
const { trigger } = useAsync((signal, id: string) =>
  fetch(`/api/usuarios/${id}`, { signal })
);

trigger("42");
```

Las funciones que solo reciben el signal no cambian:

```ts
useAsync((signal) => fetch("/api/config", { signal }));
```

Las funciones que no necesitan cancelación pueden omitirlo:

```ts
useAsync(() => cargarPreferencias());
```

**Por qué:** agregar el signal al final causaba tres problemas:

1. Si tu función no declaraba el signal, el tipo de `trigger` perdía su último argumento real: `useAsync((id: string) => …)` generaba un `trigger()` que rechazaba `trigger(id)`.
2. Los parámetros opcionales pasaban a ser obligatorios en `trigger`.
3. Con parámetros opcionales, llamar a `trigger` con menos argumentos ponía el signal en el parámetro equivocado en runtime.

Con el signal primero, `trigger` recibe exactamente los parámetros declarados después de él.

:::tip[Encontrar los usos]
Buscá `useAsync(` en tu código y revisá la lista de parámetros de cada función. TypeScript marca cada llamada cuyo primer parámetro no sea compatible con `AbortSignal`.
:::

## `useDocumentTitle` está deprecado {/* #usedocumenttitle-is-deprecated */}

React 19 permite renderizar [`<title>`](https://react.dev/reference/react-dom/components/title) desde cualquier componente y lo sube al `<head>`. El hook sigue funcionando en 1.x y muestra un aviso una sola vez fuera de producción. Se va a eliminar en 2.0.

```tsx
// ❌ Deprecado
function Bandeja({ cantidad }: { cantidad: number }) {
  useDocumentTitle(`Bandeja (${cantidad})`);
  return <ListaMensajes />;
}

// ✅ React 19
function Bandeja({ cantidad }: { cantidad: number }) {
  return (
    <>
      <title>{`Bandeja (${cantidad})`}</title>
      <ListaMensajes />
    </>
  );
}
```

Cuando el componente se desmonta, React quita su `<title>` y vuelve a aplicar el anterior, igual que el comportamiento por defecto del hook. No hay un equivalente directo para `persistOnUnmount: true`. En ese caso, renderizá el título desde un componente que quede montado.

## Fixes de comportamiento {/* #behaviour-fixes */}

No son cambios de API, pero cambian comportamientos de los que quizás dependías:

- **`useDebounce`**: ahora respeta `delay={0}`. Antes, `0` terminaba siendo 500 ms.
- **`useDelay`**: el runner manual devuelve una función para cancelar, y los timers pendientes se limpian al desmontar.
- **`useQueryParams`**:
  - `set({})` elimina el query string. Antes no hacía nada.
  - `set` y `clear` conservan el hash de la URL.
  - `build` ignora valores `null`/`undefined` en vez de tirar error, y serializa objetos y arrays como JSON.
  - `get` ya no convierte a número `" "`, `"0x10"`, `"1e5"`, `"007"` ni enteros mayores a `Number.MAX_SAFE_INTEGER`; quedan como strings.
  - Todas las instancias montadas se vuelven a renderizar con `set`, `clear` y la navegación del navegador.
- **`useLocalStorage`**: `getItem` devuelve `null` para valores que no son JSON válido en vez de tirar error, y `hasItem` devuelve `true` para items guardados como string vacío.
- **EventContext**: ya no usa `crypto.randomUUID()`, así que funciona en HTTP plano y en navegadores viejos.
